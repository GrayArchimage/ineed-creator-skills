# 兼容性优先维护规则

已发布游戏、旧 SDK、旧技能包在平台升级后必须继续正常使用原有能力；新 SDK 面对旧平台必须协商协议、查询能力并明确失败。兼容性包括参数、默认值、返回值、错误码、事件顺序、配置含义、存档格式以及支付和奖励语义。

不得默认删除旧接口、改变旧语义、强迫重新导出，或用自动迁移绕过要求。标记废弃不是删除授权。

功能需求与兼容性冲突，或无法证明兼容时，暂停受影响变更的发布，明确通知负责的平台或 SDK 开发者。由开发者决定调整方案、延期，或明确批准范围内的例外；不相关工作可继续。创作者选择功能或界面不构成破坏兼容性的批准。

例外记录必须包含：冲突需求、受影响版本及作品、替代方案、迁移和回滚步骤、负责开发者对明确范围的批准。每次发布记录兼容结论，测试旧游戏/旧插件+新平台、新插件+旧平台、旧下载链接、旧存档恢复。保留历史契约和固定版本制品。
