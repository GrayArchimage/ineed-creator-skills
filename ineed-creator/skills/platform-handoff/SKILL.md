# 与 iNeed 沟通配置需求

接入代码和平台配置是同一份需求的两端。先阅读工程、现有配置与用户原话，再按下方模板输出交接单，交给创作者复制到 iNeed 的作品对话。不要让用户从代码中猜商品标识或入口位置；不得把示例当成用户批准的价格和权益。

## AI 的工作

1. 区分已确认、建议、待确认、冲突。保留必填、选填、暂不启用和原始备注；没有答案写“待确认”，不能填 0 伪装已确认。可从代码确认的入口写出菜单路径、按钮名称、快捷键及对应脚本/事件。
2. 先询问会阻塞当前接入的缺项。平台 AI 可以回答已有配置/项目/平台数据的问题、按指定时间范围分析资料、整理建议；分析结果不是修改授权。用户明确说“应用”时才更新相应平台表单。说明读取的是草稿还是线上配置，外部资料注明来源和日期，未检索不得声称已核实。
3. 功能配置仅覆盖登录、支付、榜单、广告、存档及已支持的联机等平台能力。备注“左右摆放广告”是位置需求，不代表已改动游戏画面；新增游戏按钮/事件/玩法需要创作者 AI 修改源工程并重新导出。平台未提供的能力保持待办，不能承诺通过对话已经实现。
4. 配置变更完成后核对 iNeed 回显的商品 key、榜单 key、广告位 key、价格、权限和启用状态，再核对源工程绑定值。仅平台侧已有绑定的服务配置变化无需重打包；源代码中空的标识不会自动绑定。发生兼容性冲突遵守 [兼容原则](../../COMPATIBILITY.md)。
5. 随交接单给出“从哪个界面点击、预期结果、失败时记录什么”的测试方案；覆盖自绘 UI 取数据和平台 UI 两种模式、取消/失败、重试与账号切换。模拟支付、广告与真实完成分开标注。

## 可复制交接单

下面是字段清单，不是平台 API 请求格式。字段是否必需随启用能力而定；逐项保留状态。凭据、令牌和私钥只通过平台安全表单填写，不放进交接单、代码或聊天附件。

```text
请基于这份交接单整理当前作品草稿；先回显已填写内容、备注和缺项。
作品：名称 / 工程类型与版本 / 上传 ZIP 文件名与 SHA256
本次操作：查询现状 / 整理待确认方案 / 按已明确需求填写草稿
发布状态：仅测试预览 / 待审核（填写草稿不等于已经上线）

登录：启用状态；允许游客进入吗；何时要求登录；登录入口路径及按钮名称；取消后是否继续游客模式；账号切换时清理哪些状态。
盈利：广告 / 买断 / 免费+内购 / 章节 / 暂不变现；可组合项和限制待平台核对。
商品（每个单独列一行）：productKey；名称；用户看到的说明；平台计价单位与价格；永久权益或消耗品；发放数量；使用/扣减时机；是否可重复购买；购买入口；到账后的游戏行为。未知项保留待确认，价格由服务端配置决定。
广告：普通展示或激励广告；placementKey；触发入口；位置备注；关闭/失败行为；激励奖励内容及数量；一次动作标识与幂等策略。左右摆放普通广告不等于激励广告，播放计时不等于可信完成凭据。
排行榜：boardKey；名称；开局/结算事件；分数公式与单位；升序/降序；同分规则；范围（世界/省/市）；赛季或重置周期；合法范围；runId 与耗时；重试保留原成绩；展示入口。
存档：保存/读取入口；数据字段与 schemaVersion；游客/账号隔离；账号切换；冲突时的选择；单份不超过 1 MiB。不要声称全部 user:// 已自动同步。
多人联机：是否需要；人数；创建/加入/重连入口；同步模型；所需平台服务；当前支持状态。Godot Web 不支持原生 ENet UDP，不承诺自动改造成可用联机。
界面分工：游戏自绘并读取平台数据 / 使用平台现成 UI；分别说明登录、商店、榜单入口。验证身份、支付确认和真实广告展示仍交给可信平台。
其他必填/选填：作品名称、简介、分类、标签、展示端、封面等，以当前作品表单要求为准。
备注原话：完整保留用户希望（例如“左右摆放广告”）。
已完成代码：入口及脚本；SDK/协议版本；已绑定标识。
待平台配置：字段与负责方。
待创作者修改：需要补源代码、重新导出或素材处理的事项。
待确认：问题 / 原因 / 可选方案。
测试证据：环境、版本、入口、实际结果；哪些是模拟、哪些是真实服务。
```

## 对话示例

“我希望通过广告盈利，左右放广告，还要两个商品。” → 可记录广告盈利和位置备注、两个待完善商品；询问两个商品卖什么、价格/权益和入口。不得自动决定价格，也不能声称左右广告已插入游戏。

“现在是什么付费模式？” → 读取当前作品配置并回答，区分草稿与已发布配置，不修改数据。

“分析 9 月 1 日到 9 月 7 日的数据，给建议。” → 标注日期、来源、缺失值与假设。用户随后说“直接应用”时，只修改已明确且平台支持的配置；涉及游戏画面的建议列为创作者待办。
