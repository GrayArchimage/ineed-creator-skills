# 版本、下载与长期维护

## 三个独立版本

| 版本 | 负责范围 | 是否需要创作者重新导出 |
|---|---|---|
| Skill 包 | AI 接入流程、文档、脚本和示例 | 仅更新文档不需要 |
| Godot 插件 / 协议 | 游戏与平台稳定通信契约 | 修改已打入游戏的插件时需要 |
| 平台运行时 | 认证、平台界面、供应商及已绑定服务 | 兼容更新通常不需要 |

商品配置、认证流程、广告供应商、平台界面可由平台更新；新增游戏事件、自绘 UI 和玩法代码仍需重新导出。每次会话固定兼容运行时，下一次启动采用灰度或回滚后的版本。

## 下载和 AI 阅读

网页正文、原始 Markdown 和 ZIP 从同一批仓库源文件生成。完整 Skill ZIP 含插件/脚本/示例；纯 Markdown ZIP 供离线阅读，不含运行插件。网页提供分类导航、原始 Markdown 链接、站点地图和 llms.txt，不要求登录或执行 JavaScript 才能读正文。

当前版本及 SHA256 以下载页 manifest 为准。平台随部署携带已验证制品，不在用户下载时临时请求 GitHub。既有下载地址保持可用；需要复现时使用固定版本的 GitHub Release。

## 维护流程

1. 修改包内 Markdown 或对应插件/脚本；新增页面时登记分类目录，保持包内相对链接有效。
2. 核对平台实现中的格式白名单和限制，再更新对应文档与机器可读清单。建议项和强制要求分开写。
3. 构建静态网页与 ZIP，校验链接、制品哈希和无 JavaScript 阅读；执行受影响的兼容检查。
4. 新建版本并记录兼容结论，保留旧 Release 及冻结契约，不覆盖历史制品。
5. 平台固定引用该版本的制品；上线后核对网页、原始 Markdown、ZIP 与版本信息一致。

## 兼容性是发布条件

遵守[兼容性原则](../../COMPATIBILITY.md)：参数、默认值、返回值、错误码、事件顺序、配置、存档、付款和奖励语义都在范围内。废弃标记不等于删除许可。发生冲突时停止受影响发布，向平台/SDK 负责开发者说明并取得明确范围的决定；创作者选择功能不构成兼容例外批准。
