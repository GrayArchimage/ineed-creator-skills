# 版本、下载与长期维护

## 三个独立版本

| 版本 | 负责范围 | 是否需要创作者重新导出 |
|---|---|---|
| Skill 包 | AI 接入流程、文档、脚本和示例 | 仅更新文档不需要 |
| Godot 插件 / 协议 | 游戏与平台稳定通信契约 | 修改已打入游戏的插件时需要 |
| 平台运行时 | 认证、平台界面、供应商及已绑定服务 | 兼容更新通常不需要 |

商品配置、认证流程、广告供应商、平台界面可由平台更新；新增游戏事件、自绘 UI 和玩法代码仍需重新导出。每次会话固定兼容运行时，下一次启动采用灰度或回滚后的版本。

## 下载和 AI 阅读

网页正文、原始 Markdown 和 ZIP 从同一批仓库源文件生成。完整 Skill ZIP 含插件/脚本/示例；纯 Markdown ZIP 供离线阅读，不含运行插件。网页提供分类导航、原始 Markdown 链接、站点地图和 llms.txt，不要求登录或执行 JavaScript 才能读正文。

当前版本及 SHA256 以下载页 manifest 为准。平台随部署携带已验证制品，不在用户下载时临时请求 GitHub。既有下载地址保持可用；需要复现时使用固定版本的 GitHub Release。

## 维护流程

1. 修改包内 Markdown 或对应插件/脚本；新增页面时登记分类目录，保持包内相对链接有效。
2. 核对平台实现中的格式白名单和限制，再更新对应文档与机器可读清单。建议项和强制要求分开写。
3. 构建静态网页与 ZIP，校验链接、制品哈希和无 JavaScript 阅读；执行受影响的兼容检查。
4. 新建版本并记录兼容结论，保留旧 Release 及冻结契约，不覆盖历史制品。
5. 平台固定引用该版本的制品；上线后核对网页、原始 Markdown、ZIP 与版本信息一致。

## 兼容性是发布条件

遵守[兼容性原则](../../COMPATIBILITY.md)：参数、默认值、返回值、错误码、事件顺序、配置、存档、付款和奖励语义都在范围内。废弃标记不等于删除许可。发生冲突时停止受影响发布，向平台/SDK 负责开发者说明并取得明确范围的决定；创作者选择功能不构成兼容例外批准。

## v0.1.4 / 插件 0.1.1

新增完整开发流程、支持边界、接口、界面建议、异常恢复和功能验收；细化五项能力 Skill。新增 ensure_logged_in、consume、buy_and_consume 包装器，购买前显式确保登录；只购买仍只购买，不自动消费。组合使用已有库存优先，部分成功显式返回，重试保持消费 ID。

协议仍为 v1，未增加远程方法、未修改平台价格/发放规则、未变更旧存档。旧插件与旧下载入口保留；已有游戏不会自动替换其打包插件。需要新包装器时创作者更新插件并重新导出；平台业务运行时后续兼容更新仍独立于游戏 ZIP。

## v0.2.0 / 实时联机插件 0.1.0

新增按作品启用的双人随机匹配、大厅和邀请；保持协议 v1 与原五项能力和插件 0.1.1 不变。提供独立 Godot WebRTC 插件、网页信令客户端及填写后可直接复制到平台聊天的交接流程。旧游戏无需重新导出；只有接入新玩法联机时更新工程。旧版本固定制品与下载入口保留。

## 0.3.0：简化 Godot 能力接入

Godot 插件 0.1.2 新增账号/昵称、商品/库存/权益、榜单配置/列表/提交包装器；实时插件 0.2.0 新增 start_game/game_ready，保留旧 start/connected。协议 v1、远程方法及旧返回不变。明确前后端分工、独立创作者到平台交接、真实与模拟验收。支付组合的未知结果和同次消费幂等语义保持不变。该版本的隔离测试不能代替真实付款/榜单业务验收。

## 0.3.1：跨设备匹配确认

补充随机匹配的同账号顶替、取消、断线和创作者/平台分工。仍用已有 Godot 实时插件 0.2.0 与平台协议 v1；旧包无需为顶替功能重新导出，新宿主负责弹窗与服务器确认。保留 0.3.0、0.2.0、0.1.5 固定下载。

## 0.3.2：交接检测与展示广告边界

修正支持表中与已发布双人实时插件矛盾的旧描述；补充创作者/平台独立交付反馈和可选展示广告 helper，明确匹配关闭、败局去重及迟到响应失效。协议 v1、INeed 插件 0.1.2 保持不变。实时插件 0.2.1 先检查宿主存在，再获取接口；本地HTTP没有宿主时返回原有 UNSUPPORTED，不制造Godot错误日志，旧 start/connected 和 start_game/game_ready 行为不变。展示 helper 需作品实际获授权，旧宿主忽略该可选消息。旧接口、下载和游戏包均保留。
