# 容量与文件数量

单位为二进制 MiB：1 MiB = 1,048,576 字节。界面中的部分历史“MB”提示使用同一字节阈值。

| 检查对象 | 当前上限 | 如何计算 |
|---|---|---|
| 上传 ZIP | 50 MiB | 外层归档实际字节；上传端点同时校验 |
| 托管资源总量 | 50 MiB | 解开 ZIP 后所有要存储资源的实际字节之和 |
| 单个存储资源 | 50 MiB | 解开 ZIP 后单个文件大小 |
| 有效资源文件数 | 500 | 不靠层层 ZIP 绕过；建议留出辅助文件余量 |
| Godot 解码总量 | 128 MiB | gzip/br 解码后资源，加上未压缩资源总量 |
| Godot 单个解码资源 | 128 MiB | 仍同时受 50 MiB 存储限制及总量限制 |
| 规范化相对路径 | 240 字符 | 包含目录及文件名 |
| 云存档 | 1 MiB | 独立业务限制，不是游戏包可用空间 |

## 两层压缩的区别

假设外层 ZIP 为 42 MiB，解开 ZIP 得到 45 MiB 资源，其中压缩 WASM 为 8 MiB、解码后 40 MiB，其余资源共 37 MiB：存储为 45 MiB，Godot 解码总量为 77 MiB。两者均需合格。将 80 MiB 原始资源用 ZIP 压到 40 MiB，仍不能通过 50 MiB 的存储限制。

Godot 的 128 MiB 是解码体积上限，不是浏览器内存保证；场景、纹理、音频与 GPU 内存可能继续增长。达到文件大小限制不代表低端手机能运行。

## 缩减建议

先移除未引用资源、编辑器缓存和重复素材，再检查纹理尺寸、音频长度/编码与字体覆盖。已压缩图片、音频、视频、WOFF2 通常无需反复压缩。Godot 字体不能只按当前测试昵称裁剪，动态商品和账号名也必须可读。

不要为了满足限制静默删除关卡、音乐或字体；把尺寸明细和取舍交给创作者。不要将同一大文件切成多个请求以绕过总量限制。
